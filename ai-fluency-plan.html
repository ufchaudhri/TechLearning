Retention Engine — learn fast and keep it

Speed without retention is wasted effort. This plan bakes in four evidence-based mechanisms. The single highest-leverage habit: after every session, spend 10 minutes recalling from memory before you look at notes.

The daily 4-step loop (≈90 min/session, 4 sessions/week): 1) Warm-up — 5-min recall of last session from memory. 2) Learn — one focused concept or build. 3) Do — apply it in code immediately, no passive watching. 4) Encode — write a 3-sentence "what I learned + where it breaks" note and schedule a review.

1 · Active recall > re-reading

Testing yourself is the strongest driver of long-term memory. Never re-watch a lecture — close it and reconstruct it.

  • End each session by answering that week's recall prompts from memory.
  • Keep a running "questions I couldn't answer" list — that's your next study target.
  • Turn key facts into flashcards (Anki) — 10 high-quality cards/week max.

2 · Spaced repetition

Review on an expanding schedule so memories are refreshed just before they fade. Apply to each week's core concepts.

ReviewWhenHow (≈10 min)
R1Day +1Recall prompts from memory
R2Day +3Re-run the code from scratch
R3Day +7Explain it to someone / a post
R4Day +21Apply it in a new mini-context

3 · Learn by building (project-first)

Your data background means you learn fastest by shipping. Every week's concept is anchored to a concrete build, not a certificate. The build is the study.

  • Type the code yourself — never copy-paste whole notebooks.
  • Deliberately break it, then fix it. Debugging cements understanding.
  • Push every build to GitHub the same day.

4 · Teach it (Feynman + build-in-public)

Explaining forces you to find the gaps — and doubles as career evidence: a public learning trail is itself a hiring signal.

  • One short LinkedIn/blog post per week: "What I built + one thing that surprised me."
  • If you can't explain it simply, you haven't learned it yet — go back.
  • Interleave: mix old and new topics in each recall so retrieval stays effortful (that's the point).

    Positioning

    Your edge in 2026 isn't raw AI skill — it's the intersection of AI + your domain analytics expertise. Lead with that everywhere.

    • Headline: "Data/analytics pro building production AI — RAG, LLM apps, evals."
    • Reframe past analytics wins as AI-adjacent: data quality, metrics, experimentation.

    Proof pieces to link

    • GitHub with 4–5 clean, README-first repos.
    • One deployed live demo (Hugging Face Spaces / Streamlit).
    • A capstone case study written like a PRD: problem → data → model → eval → impact.

    For the AI Product path

    • Speak MLOps, feedback loops, eval, and data quality fluently.
    • Write one "AI feature spec": scope, risks, metrics, guardrails.
    • Practice the "how would you evaluate this model?" interview question.

    For the AI Eng path

    • Depth on Python, one cloud (AWS/GCP/Azure), Docker, and a CI step.
    • Show a served model + monitoring, not just a notebook.
    • Do a few LLM/ML system-design mocks before applying.

    How to run this plan

    • Cadence: 4 sessions/week × ~90 min + one 1-hour weekly review/ship ≈ 7 hrs — the middle of your 6–10 range, with room to push.
    • Non-negotiable: every week ends with something pushed to GitHub and one public post. No shipping, no moving on.
    • Progress saves to this browser automatically. Re-open the artifact anytime and hit Reload in the header to refresh.
    • Order matters for weeks 1–4 (they compound). Weeks 5–6 can swap by target role: Agents-heavy for product, MLOps-heavy for engineering.
    • Stuck? Timebox debugging to 30 min, then write down the blocker and move on — recalling the blocker is itself learning.
